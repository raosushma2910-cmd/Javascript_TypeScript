JavaScript foundations

Chapters 01-05
Syntax, values and operators

01

JavaScript basics

JavaScript source is parsed and executed by a runtime such as Node.js or a browser. Start with a statement, then inspect its output.

console.log("Hello, world!");
const total = 2 + 3;
console.log(total);
Remember: Node runs a JavaScript file with node path/to/file.js.
02

Keywords and identifiers

Keywords have a language-defined role; identifiers are names you choose for variables and functions. Names are case-sensitive and cannot be reserved words.

const userName = "Sam";
function showStatus() { return "ready"; }
Remember: choose descriptive names; use a consistent naming style.
03

Literals and primitive values

A literal writes a value directly in code. Keep null (intentional empty value) distinct from undefined (missing or not assigned).

KindExampleQuick note
Number42, 3.14Also includes NaN and infinities.
Text"hello", `Hi ${name}`Backticks interpolate expressions.
Other primitivestrue, null, undefinedEach has different meaning.
04

Operators

Operators combine values: arithmetic (+ - * / %), assignment (=), comparison, logical (&& || !) and conditional (? :).

const isReady = status === "pass" && retries < 3;
const label = isReady ? "Run" : "Wait";
Remember: prefer === and !== to avoid implicit type conversion surprises.
05

Increment, decrement and nullish coalescing

++x changes then yields the value; x++ yields the old value then changes. ?? supplies a fallback only for null or undefined.

let count = 4;
const oldCount = count++;
const shownName = name ?? "Guest";
Remember: ?? preserves valid falsy values such as 0 and ""; || does not.

Decisions and input

Chapters 06-08
Choose a path and read values

06

Conditional statements

Use if / else if / else when conditions need different blocks. Use a ternary for one short value choice, not a long sequence of actions.

const result = score >= 70 ? "Pass" : "Retry";
if (score >= 70) {
  console.log("Pass");
} else {
  console.log("Retry");
}
07

switch statements

Use switch to compare one expression with several case values. Add break when a case should stop rather than fall through.

switch (responseCode) {
  case 200: message = "OK"; break;
  case 404: message = "Not found"; break;
  default:  message = "Other status";
}
Remember: include a default for values that do not match a case.
08

User input in the browser and Node.js

Input usually arrives as text. Convert it before numeric work and validate it before using it. Node examples use standard input modules such as readline or fs.

const number = Number(input);
if (Number.isFinite(number)) {
  console.log(number % 2 === 0 ? "Even" : "Odd");
}
Remember: Number("abc") is NaN; check input rather than assuming it is valid.

Loops and arrays

Chapters 09-12
Repeat work and handle lists

09

for loops

A for loop keeps setup, continuation condition and update together. Check the boundary (< versus <=) to avoid an extra or missing iteration.

for (let i = 0; i < items.length; i++) {
  console.log(items[i]);
}
10

while loops

A while loop checks before each pass. It may run zero times; update the state so the condition can eventually become false.

let age = 7;
while (age <= 10) {
  console.log(age);
  age++;
}
11

do...while and nested loops

do...while checks after the body, so it runs at least once. Nested loops are useful for grids, matrices and patterns; the inner loop completes for each outer pass.

let attempt = 0;
do {
  attempt++;
} while (attempt < 1);
Remember: nested loops multiply the amount of work; trace both counters.
12

Arrays and array methods

Arrays are ordered, zero-indexed lists. Use push / pop at the end, find for one match, filter for matches, and map to transform each item.

const scores = [45, 82, 91, 60];
const passing = scores.filter(score => score >= 70);
const labels = scores.map(score => score >= 70 ? "Pass" : "Retry");
Remember: default sort() compares text-like values; numbers need nums.sort((a, b) => a - b).

Functions and language mechanics

Chapters 13-16
Reuse behavior and understand scope

13

Functions

A function packages behavior. Parameters receive inputs; return sends a result back. Function declarations, expressions and arrow functions are common forms.

function hasError(...codes) {
  return codes.some(code => code >= 400);
}
hasError(200, 404);
Remember: rest (...args) collects arguments; spread (...items) expands an iterable.
14

var, let, const, hoisting and TDZ

DeclarationScopeKey reminder
varFunctionCan be redeclared; hoisted and initialized as undefined.
letBlockCan be reassigned; unavailable in its temporal dead zone before declaration.
constBlockBinding cannot be reassigned; object contents may still change.
Remember: prefer const; use let when reassignment is needed; avoid var in new code.
15

Closures, references and copying

A closure keeps access to its outer lexical variables after the outer function returns. Objects are reference values: assigning one variable to another does not clone the object.

function makeCounter() {
  let count = 0;
  return () => ++count;
}
const next = makeCounter();
next(); // 1
Remember: object spread makes a shallow copy; nested objects remain shared. structuredClone can make a deep copy of supported data.
16

Strings

Strings are immutable text values. Template literals use backticks for interpolation and multiline strings. Search with methods such as includes, startsWith and indexOf.

const message = `Test completed in ${elapsed}ms`;
const isStaging = url.includes("staging");
Remember: a method that returns a new string does not change the original variable unless you assign the result.

Objects, callbacks and promises

Chapters 17-20
Model data and async results

17

Objects

Objects group named properties and methods. Access with dot or bracket notation; bracket notation is useful for a key stored in a variable. Destructuring can unpack properties, and names are case-sensitive.

const test = { status: "pass", code: 200 };
console.log(test.status);
console.log(test["code"]);
Remember: when copying nested objects, know whether the copy is shallow or deep.
18

Multidimensional arrays

An array of arrays represents rows and columns. Use one index per dimension; nested loops can visit every cell or produce left, right and pyramid patterns.

const matrix = [["login", "pass"], ["cart", "fail"]];
for (let row = 0; row < matrix.length; row++) {
  for (let col = 0; col < matrix[row].length; col++) {
    console.log(matrix[row][col]);
  }
}
19

Callbacks

A callback is a function passed to another function to run later or at a chosen point. Nested asynchronous callbacks can become hard to follow ("callback hell").

function placeOrder(item, callback) {
  console.log("Placed:", item);
  callback();
}
placeOrder("Burger", () => console.log("Ready"));
Remember: asynchronous callbacks do not make surrounding code wait; order may differ from source order.
20

Promises

A promise is pending, then fulfilled or rejected. Handle success with .then, failure with .catch, and cleanup with .finally.

MethodUse
Promise.allWait for all to fulfill; rejects if one rejects.
Promise.allSettledGet every fulfilled/rejected outcome.
Promise.raceUse the first promise to settle.
fetchData()
  .then(data => console.log(data))
  .catch(error => console.error(error))
  .finally(() => console.log("done"));

Async, modules and Playwright

Chapters 21-24
Coordinate work and test a browser

21

Async/await and execution order

async functions return promises. await pauses that function until a promise settles, without blocking the whole JavaScript runtime. Use try/catch for failures.

async function loadUser() {
  try {
    const user = await getUser();
    return user;
  } catch (error) {
    console.error(error);
  }
}
Remember: sequential awaits are easy to read; independent work can often run together with Promise.all([...]).
22

Import and export

Modules split code into files. Export reusable values and import them where needed. Keep the module syntax and Node/project configuration consistent.

// utils.js
export const BASE_URL = "https://api.example.com";

// app.js
import { BASE_URL } from "./utils.js";
23

Classes and objects

A class describes the data and behavior shared by its instances. Create an instance with new; class methods are written without the function keyword.

class Person {
  eat() { return "eating"; }
}
const person = new Person();
24

Playwright project setup

The 24_PlayWright folder contains the Playwright test package setup. The small spec examples are in chapter 21: a test receives a page, navigates, and asserts a result.

test("opens the page", async ({ page }) => {
  await page.goto("https://playwright.dev/");
  await expect(page).toHaveTitle(/Playwright/);
});
Remember: use await for browser actions and rely on Playwright's web-first assertions to wait for expected conditions.

Classes and object-oriented programming

Chapters 25-28
Build objects with clear responsibilities

25

Constructors, visibility and static members

The constructor initializes each new instance. Instance members belong to one object; static members belong to the class. JavaScript private fields use #.

class Credentials {
  #apiKey;
  constructor(user, key) {
    this.user = user;
    this.#apiKey = key;
  }
}
Remember: keep sensitive/internal state private and expose only the operations the caller needs.
26

Encapsulation

Encapsulation keeps an object's state behind a small public interface. Validate changes inside methods rather than letting callers mutate important state freely.

class BankAccount {
  #balance = 0;
  getBalance() { return this.#balance; }
  deposit(amount) {
    if (amount > 0) this.#balance += amount;
  }
}
27

Inheritance

A subclass can reuse and specialize a base class with extends. Call super when the parent constructor or behavior is required. The exercises compare single, multilevel, hierarchical and hybrid relationships; JavaScript classes have one direct superclass, while mixins can compose extra behavior.

class Browser {
  open() { return "open"; }
}
class ChromiumBrowser extends Browser {
  open() { return super.open() + " Chromium"; }
}
28

Polymorphism

Different objects can answer the same method call in their own way. Runtime method overriding lets code work with a common interface while behavior varies by actual object.

function run(browser) {
  console.log(browser.open());
}
run(new ChromiumBrowser());
Remember: prefer a clear shared contract over long type checks for each subclass.

31

TypeScript basics, functions and special types

TypeScript adds static checks to JavaScript. Annotations describe expected values; they help catch mistakes before runtime and are erased from emitted JavaScript.

function greet(name: string): string {
  return `Hello, ${name}!`;
}
const multiply = (a: number, b: number): number => a * b;
TypeMeaningGood reminder
anyOpt out of type checking.Avoid when possible.
unknownValue not yet known.Narrow or validate before use.
voidNo useful return value.Common for logging functions.
neverFunction does not finish normally.For throwing or endless functions.
function show(value: unknown): string {
  if (typeof value === "string") return value;
  return String(value);
}
Remember: unknown is safer than any because it requires a check before use.
